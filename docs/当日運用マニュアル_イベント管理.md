# 当日運用マニュアル（イベント管理）

最終更新: 2026-10-05
対象: イベント管理者、当日運営責任者
関連: [サークル管理マニュアル](./当日運用マニュアル_サークル管理.md)

## この画面で行うこと

イベント全体の注文状況、在庫切れ、スタッフへの連絡、来場者・リストバンド、売上集計を管理します。画面は `/event/dashboard` です。ヘッダーのスペース切り替えで対象イベントを選んでから開いてください。別イベントを選んだまま操作すると、別のイベントに対する操作になります。

画面の左メニューは「運営」「売上・分析」「管理」「拡張」に分かれています。開催中によく使うのは「注文モニタ」「在庫・売り切れ」「一斉アナウンス」です。

## 開場前チェック

1. ヘッダーで対象イベント名を確認します。画面タイトルにもイベント名が表示されます。
2. 「イベント設定」で開催状態、支払い方法、来場者向け設定を確認します。支払い方法を変更した場合、各サークルの対応支払い方法も確認してください。
3. 「サークル管理」で当日参加するサークルが登録済みか確認します。
4. 「スタッフ管理」で当日の担当者が有効な所属として登録され、招待が必要な担当者は参加を完了しているか確認します。
5. 「在庫・売り切れ」で売り切れ状態と在庫少数の表示を確認します。
6. 店頭端末・ネットワーク・権限を担当者ごとに確認します。権限がない場合、画面に項目が見えても保存操作はサーバー側で拒否されます。

## 開催中の基本手順

### 注文の遅れを確認する

1. 「注文モニタ」を開きます。
2. 「LIVE」が有効か確認します。無効の場合は一覧が自動更新されないので、必要に応じて手動で再読み込みします。
3. 「未着手」「調理中」の注文と経過時間を見て、遅れているサークルに連絡します。
4. 表示が止まった、または一覧の読み込みに失敗した場合は、その画面のエラー表示と再試行を確認します。集計がゼロでも、通信エラー中は売上ゼロと判断しないでください。

### 売り切れ・在庫を確認する

1. 「在庫・売り切れ」を開き、「問題のみ」で売り切れ・在庫少数の商品を絞り込みます。
2. 「LIVE」の表示状態を見てください。無効なら自動更新されません。
3. 販売停止が必要な商品は、サークルへ連絡して「サークル画面 > メニュー管理」または在庫管理で更新してもらいます。イベント側の一覧は状況確認用です。
4. 在庫少数の判定は、在庫管理を有効にしたサークルの商品に限られます。在庫管理を使わない商品の残数は比較できず、売り切れ状態だけが対象です。

### 全スタッフへ連絡する

1. 「一斉アナウンス」から新規作成を開きます。
2. 件名と本文を確認し、「全スタッフに送信する」を押します。
3. 完了メッセージの送信人数を確認します。重要な変更は口頭・現場掲示など別経路でも伝達してください。

### 来場者・リストバンドの問い合わせに対応する

1. 「リストバンド管理」で呼出IDや来場者を検索します。
2. 対象者を特定してから詳細を開きます。ニックネームや呼出IDを本人に確認し、似た名前の別人を選ばないようにします。
3. 紛失・交換、プロフィール修正、アカウント制限など必要な変更だけを行い、保存後に対象者を再確認します。
4. リストバンドの解除・再発行に伴う案内は、本人が新しいQRを使えることまで確認します。

## 売上確認と終了時

- 「全体売上管理」はサークルごとの注文一覧を集め、`completed` 状態の注文を売上・完了件数として集計します。処理中や未着手の注文は売上に入りません。
- 「統計・分析」はイベントの集計を見る画面です。対象期間・集計項目を確認してから判断します。
- 「精算」は集計売上に対する手数料率を入力して、手数料とサークル取り分を試算し、CSVに出力する画面です。ここで送金や精算確定は行われません。率は画面上の入力値で、保存されません。正式な精算額は会計担当が別途確認してください。
- 「日次締め」は対象日を選び、その日の集計を確認・CSV出力する画面です。データをロックしたり、注文受付を停止したり、締め処理を確定したりする機能ではありません。日付は当日の日本時間が初期値で、未来日は選択できません。
- 終了後に変更操作ができなくなった場合は、「イベント設定」の開催状態を確認します。イベントが終了・アーカイブ状態だと管理画面は読み取り専用になります。現場判断で再開状態へ戻さず、イベント責任者に確認してください。

## 画面の一覧

| メニュー | 用途 | 当日の確認ポイント |
|---|---|---|
| 注文モニタ | 全サークルの未着手・調理中注文を監視 | LIVEの有効状態、遅延、取得エラー |
| 在庫・売り切れ | サークル商品の在庫状況を確認 | 在庫管理の対象商品か、売り切れの反映 |
| 一斉アナウンス | イベントスタッフへ一斉連絡 | 件名・本文・送信人数 |
| リストバンド管理 | 来場者、紛失、プロフィール等を管理 | 本人特定、保存後の再確認 |
| 全体売上管理 | サークル別の売上を確認 | 完了注文だけが売上に含まれる |
| 統計・分析 / レビュー / 来場者行動・混雑 | イベント全体の状況を把握 | 集計時点と対象範囲 |
| 精算 / 日次締め | 試算・日別集計の確認とCSV出力 | 確定・送金・受付停止機能ではない |
| サークル管理 | サークルの登録内容と運用状態を確認 | サークル側の作業は担当者へ依頼 |
| スタッフ管理 | イベントスタッフと招待を管理 | 招待の受諾状況、権限、解除対象 |
| イベント設定 / 契約状況 | イベント情報と契約の確認 | 開催状態の変更は責任者に限定 |
| データエクスポート | イベントデータをCSV等で出力 | 出力先・共有先・対象期間を確認 |
| 抽選 | 有効化されている場合の抽選運用 | メニューに表示されていることを確認 |

## 間違えやすい内部仕様・トラブル対応

- **売上が急に少なく見える**: 全体売上管理は各サークルの注文一覧を取得します。個別サークルの取得に失敗すると、そのサークルの注文を空として集計する実装です。全体通信エラーが出ていなくても一部だけ欠ける場合があるため、再読み込みし、必要なら該当サークル画面の売上と照合してください。
- **全体売上とサークル側の数字が一致しない**: 画面によって対象日、集計項目、注文状態が異なります。売上比較は同じ日付・同じ状態・同じ集計画面で行ってください。サークル側の統計には総注文数と完了率も表示されます。
- **画面を開きっぱなしにしている**: LIVE更新は画面ごとに独立しています。注文モニタや在庫・売り切れの自動更新ボタンが無効なら、表示値は最新とは限りません。
- **締めたつもりなのに注文が続く**: 「日次締め」は集計確認とCSV出力です。受付を止める操作ではありません。受付の終了はイベント責任者が開催状態・運用設定を確認して行ってください。
- **保存・管理ボタンが使えない**: 選択中のスペースとロールを確認します。ブラウザーに保存された画面状態だけでは権限は付与されず、APIが実際の所属・権限を検証します。
- **イベント設定を誤って変更した**: 追加の設定変更を止め、責任者へ変更箇所と時刻を共有します。開催状態や支払い方法の変更は、来場者・サークル双方の運用に影響します。
